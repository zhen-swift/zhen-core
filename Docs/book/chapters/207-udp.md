# 7 · UDP and the fourth state

![A UDP port can answer four ways: a datagram, "port unreachable", some other ICMP error, or silence.](figures/07-hero.svg)

::: short
The short version

- UDP has no handshake. You send one datagram and wait.
- An open UDP port often **says nothing**, so silence proves nothing. Zhen calls it **open|filtered**, the fourth state.
- A **connected** UDP socket hears ICMP errors as an `errno`. That's how "closed" is told apart from silence, without root.
- Zhen sends **real requests** (DNS, NTP, SNMP and others) so an open port has something to answer.
- It sends **twice**, then stops. More would only use up the target's ICMP budget.
:::

## A `connect()` that sends nothing

![An unconnected socket never hears the ICMP error; a connected one gets it as ECONNREFUSED.](figures/07-connect.svg)

- On TCP, `connect` does the handshake. On UDP, `connect` **sends nothing at all** (`UDPProbe.swift:102-103`).
- It changes two things inside the castle:
  - only that one peer's datagrams get into the mailbox;
  - the kernel now **hands ICMP errors for that peer** to the socket.
- An unconnected socket "never hears about ICMP errors". A connected one gets a port-unreachable as `ECONNREFUSED` on its next read. "That is how 'closed' is told apart from silence without a raw socket" (`UDPProbe.swift:11-15`).
- No privilege is needed, so this runs everywhere the TCP connect scan runs (`UDPPortScan.swift:20-22`).

```swift
if received < 0 {
    switch errno {
    case ECONNREFUSED: return .refused
    case EHOSTUNREACH, ENETUNREACH, EHOSTDOWN, ENETDOWN: return .unreachable(errno)
    default: return nil
    }
}
```

::: word
New word: port unreachable

When a datagram reaches a UDP port nobody is listening on, the host usually sends back an ICMP **"port unreachable"** message. It's UDP's version of TCP's RST, and a connected socket sees it as `ECONNREFUSED`.
:::

## One class, two shapes

![A bound socket talks to many hosts; a connected socket talks to exactly one and hears its ICMP errors.](figures/07-shapes.svg)

There used to be two copies of the same UDP socket code, and the port scan would have made three. Now there's one class, `UDPProbe`, in two shapes (`UDPProbe.swift:1-15`):

- **Bound**: one socket for many hosts. It's bound to the interface's own address on an ephemeral port, and `sendto` names each destination (`UDPProbe.swift:71-98`). NetBIOS and SSDP use it (chapter 9).
  - **Why the address?** "The source address of a query decides where the reply is sent", and a Mac with a VPN has more than one.
  - **Why an ephemeral port?** So it doesn't fight whatever already owns the well-known port, "Samba on 137, a media server on 1900".
- **Connected**: one socket for one host and port. It uses `send` and hears ICMP errors (`UDPProbe.swift:100-114`). The UDP port scan uses it.

Both shapes share the rest:

- non-blocking, and read through a `DispatchSource` (chapter 4);
- `recvfrom` into a `sockaddr_storage`, which fits IPv4 or IPv6 (chapter 3), with a 2 KB buffer (`UDPProbe.swift:209-228`);
- each wake-up **drains everything** that's ready, because one `ssdp:all` search can bring "sixty datagrams in a burst" (`UDPProbe.swift:177-183`);
- **only the cancel handler closes the ticket**. A flag, `sourceOwnsDescriptor`, makes sure that `deinit` never closes it a second time (`UDPProbe.swift:60-69`, `:184-188`).

## Send twice, then listen

![Send at the start, send once more at 40% of the budget, and call silence at the end open|filtered.](figures/07-timeline.svg)

1. Start listening, **then** send (`UDPPortScan.swift:159-160`).
2. At **40%** of the budget, send **once more**. "UDP is lossy and a single lost datagram would otherwise become `open_filtered` on a port that is plainly open" (`UDPPortScan.swift:153-157`).
3. Never a third time: "every resend is another ICMP the target may rate-limit".
4. The first thing that comes back decides it:

| What came back | Zhen says |
|---|---|
| any datagram, even an empty one | **open** |
| `ECONNREFUSED` | **closed** |
| `EHOSTUNREACH`, `ENETUNREACH`, `EHOSTDOWN`, `ENETDOWN` | **filtered** |
| nothing, by the end of the budget | **open\|filtered** |
| cancelled, or the socket couldn't open | no result at all |

The rule lives in one place (`UDPPortScan.swift:137-151`, `:191-216`).

- **Why not just "filtered"?** "Silence on TCP is `filtered` because a live TCP stack answers every SYN. Silence on UDP is not evidence of anything" (`UDPPortScan.swift:9-11`).
- **Why only 32 at a time?** TCP runs up to 512 knocks at once. For UDP "the constraint is not our descriptors but the target's ICMP budget" (`UDPPortScan.swift:43-48`).

::: word
New word: open|filtered

**open|filtered** means "maybe open, maybe blocked: we can't tell". It's the honest name for a silent UDP port, and the artifact spells it `open_filtered`.
:::

## Ask something worth answering

![Six ports get a real request in their own protocol. Every other port gets an empty datagram, and nothing ever tries a password.](figures/07-payloads.svg)

An open UDP port usually ignores an empty datagram. A request in its own language turns that silence into an answer (`UDPPayloads.swift:3-6`).

| Port | Service | What Zhen sends |
|---|---|---|
| 53 | DNS | a query for the root's name servers |
| 123 | NTP | a 48-byte client request |
| 137 | NetBIOS | a node-status query (chapter 9) |
| 161 | SNMP | a version 3 "discovery" request |
| 1900 | SSDP | an `M-SEARCH` (chapter 9) |
| 5353 | mDNS | "which services are here?" |

The table is `UDPPayloads.swift:52-69`; its summary is at `:8-13`.

- **Any other port** gets an empty datagram. An answer still means open and an ICMP error still means closed. The table only helps open ports get heard (`UDPPayloads.swift:21-23`).
- **No passwords, ever.** SNMP version 1 with the community string `public` would answer more often. But "a community string is a password, and trying the default one is a login attempt" (`UDPPayloads.swift:15-19`).
- **The answer names the service, not the table.** A reply that parses as DNS makes the port `dns`. A reply that doesn't parse still makes it open, but leaves it unnamed (`UDPPayloads.swift:25-29`, `UDPPortScan.swift:195-205`).

```swift
static let ntpRequest: [UInt8] = [0x23] + [UInt8](repeating: 0, count: 47)

static func isNTPServerReply(_ reply: [UInt8]) -> Bool {
    reply.count >= 48 && reply[0] & 0x07 == 4
}
```

[`UDPPayloads.swift:102-107` @ 0.9.0 (doc comments trimmed)]{.src}

`0x23` packs "version 4, mode 3 (client)" into one byte. A server answers in mode 4.

::: gotcha
⚠️ Gotchas the code remembers

- **Scanning from an unconnected socket.** It never hears ICMP errors, so every closed port would look like silence.
- **An error hiding in `send`.** An ICMP error can come back from the *next* `send` instead of from the reader, and "an error consumed here is one the reader never sees". Zhen checks both sends for `ECONNREFUSED` (`UDPProbe.swift:154-159`, `UDPPortScan.swift:176-179`).
- **Spinning on a strange `errno`.** Anything that isn't a known ICMP error ends the drain loop. Otherwise an error "that never clears" would spin it forever (`UDPProbe.swift:235-238`).
- **Ignoring an empty reply.** "A zero-length datagram is still a datagram, and from a connected peer it is still an answer" (`UDPProbe.swift:241-242`).
- **Rate limits.** Linux sends about **one** port-unreachable per second by default. A rate-limited "closed" arrives as silence and becomes open|filtered, which is "honest (we do not know) and lossy". "No concurrency setting changes a limit enforced at the target" (`UDPPortScan.swift:26-29`).
:::

::: remember
🧠 Remember

- UDP has **four** answers: open, closed, filtered and **open|filtered** (silence).
- `connect()` on UDP sends nothing, but it lets the kernel **tell you about ICMP errors**.
- Send a real request, twice at most, and let the **answer**, not the port, name the service.
:::
