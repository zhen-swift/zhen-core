# 16 · From a tap to a syscall

![One tap on Scan, twelve steps down, and Pip arrives at the castle's first network door.](figures/16-hero.svg)

::: short
The short version

- Tapping **Scan** doesn't start a scan. It hangs a fresh **token** on the model, and one `.task(id:)` notices and runs the scan.
- The scan goes down twelve steps: app → engine → kernel. The first network door is `socket(AF_INET, SOCK_DGRAM, IPPROTO_ICMP)`.
- Answers come back up **two channels**: a lossy one for the live counter, and a lossless one for the result.
- The list on screen comes from **history**, never from the live events.
- Sockets never run on the main actor. A **target boundary** keeps them off, not an annotation.
:::

## Down the stairs

![Twelve steps from the Scan button to store.record. Green is the app, purple is the engine, grey is a door into the kernel.](figures/16-stairs.svg)

1. **One model.** The app makes one `NetworkModel` and hangs the scan host on the root view: `.scanHost(model)` (`zhen-ios/Zhen/ZhenApp.swift:5`, `:11`).
2. **Tap.** The toolbar's Scan button calls `model.startScan()` (`zhen-ios/Zhen/Features/DevicesView/DevicesView+ToolbarView.swift:27-28`).
3. **A token.** `startScan` only notes the request, clears the live counters and sets `scanToken = UUID()` (`zhen-ios/Zhen/Model/NetworkModel.swift:106-112`). No work yet.
4. **The task wakes.** `.task(id: model.scanToken) { await model.performScan() }` is the **only** place a scan starts (`zhen-ios/Zhen/App/ScanHost.swift:14`).
5. **Stream + watcher.** `performScan` makes a progress stream with `ProbeStream.sinking(buffering: .progress)`, starts a watcher task that counts hosts, then awaits the runner (`zhen-ios/Zhen/Model/NetworkModel.swift:121-147`).
6. **A new runner, every time.** `LiveScanRunner` is an actor. It builds a fresh `ScanRunner(store:capture: .directOnly)` for each request (`zhen-ios/Zhen/Scanning/LiveScanRunner.swift:48-50`), because "an iPad changes networks under a long-lived app" (`:7-9`).
7. **Build the scanner.** `ScanRunner.init` calls `DarwinScanner.make` (`ScanRunner.swift:77-95`), the fork from chapter 15.
8. **First doors.** `getrlimit` and `setrlimit` raise the ticket limit (`DarwinPlatform.swift:86`, `:95`); `getifaddrs` lists the interfaces (`Interfaces.swift:28`).
9. **First network door.** The sweep opens its socket (`ICMPSweep.swift:277`): `socket(AF_INET, SOCK_DGRAM, IPPROTO_ICMP)` (`ICMPSocket.swift:81`), then one `sendto` per address (`:250`). Chapter 5.
10. **Names.** Bonjour first: `DNSServiceCreateConnection` (`MDNSBrowser.swift:524`). Then NetBIOS for whoever is still unnamed (`NameResolver.swift:138-142`). Chapter 9.
11. **Ports, only if asked.** One `socket(…, SOCK_STREAM, IPPROTO_TCP)` and one non-blocking `connect` per port (`TCPConnectScan.swift:176`, `:194`). Chapter 6.
12. **Write it down.** `store.record(report)` puts the run into history (`ScanRunner.swift:273`).

## Starting and stopping

![Scan hangs a fresh token on the hook and the task runs. Stop takes it off and the task is cancelled.](figures/16-token.svg)

- **Start**: a new `UUID` is a new `id`, so SwiftUI starts the task. (`startScan` refuses while anything is already running, `:107`.)
- **Stop**: `stopScanning()` sets the token to `nil` (`zhen-ios/Zhen/Model/NetworkModel.swift:115-118`). The `id` changes, so SwiftUI **cancels** the running task.
- **Leave the screen**: the view goes away, and so does its task.
- **Why one place?** A scan started from a stray `Task { }` has no owner, so nothing can stop it (`zhen-ios/Zhen/App/ScanHost.swift:3-7`).

```swift

  scanRequest = ScanRequest(ports: ports)
  liveFound = 0
  liveDegradations = []
  scanToken = UUID()
}
```

## Back up: two channels

![Progress goes in a bucket that may spill. The result travels as a sealed parcel that never does.](figures/16-channels.svg)

This is the core design, stated at the top of `ScanRunner.swift:9-14`.

- **Progress, may drop.**
  1. The engine calls a `ProgressSink` from deep inside its loops.
  2. The sink feeds an `AsyncStream` that keeps the **newest 4,096** events and drops older ones (`ProbeStream.swift:37`).
  3. The watcher, on the main actor, counts `.hostFound` and collects `.degraded` for the live view (`zhen-ios/Zhen/Model/NetworkModel.swift:124-132`).
- **Result, never dropped.**
  1. `ScanRunner.run` **returns** a `CompletedScan`. It's a return value, so nothing can fall out of it.
  2. `LiveScanRunner` wraps it: `ScanOutcome.finished` (`zhen-ios/Zhen/Scanning/LiveScanRunner.swift:28`).
  3. The model then **reloads from history** (`zhen-ios/Zhen/Model/NetworkModel.swift:145`, `reload()` at `:86-91`). The device list never comes from progress events.

::: word
New word: main actor

The **main actor** is the one lane where all UI work happens, one thing at a time. Anything slow on it freezes the screen. In zhen-ios's app target everything is on the main actor unless it says otherwise.
:::

## Keeping sockets off the main actor

![The app target lives on the main actor. The engine lives behind a target boundary, off it. Work crosses with await; events come back.](figures/16-actors.svg)

- **The app target** sets `SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor` (`zhen-ios/project.yml:57`). Good for UI.
- **The engine targets** use `.defaultIsolation(nil)` (`Package.swift:30`, `:45`). Main-actor-by-default "would silently hop every socket helper onto the main actor and serialize the scan behind the UI" (`Package.swift:14-16`).
- **Why a separate target?** "A target boundary is what keeps a socket off the main actor; an annotation is what somebody eventually deletes" (`Package.swift:85-87`). That's why `ZhenScan`, the app's adapter, lives in zhen-core and not in the app.
- **On the app side**, the seam is a `nonisolated protocol ScanRunning` (`zhen-ios/Zhen/Scanning/ScanRunning.swift:47`), and `LiveScanRunner` is an `actor`.
- **The ICMP socket** goes one step further: its actor runs on its own dispatch queue, not the shared pool (`ICMPSocket.swift:51-55`).
- **Even Diagnostics** runs its checks `@concurrent`, off the main actor (`zhen-ios/Zhen/Platform/CapabilityProbe.swift:29-33`).

::: honest
🔍 Honest note: "constructed once"

`ScanRunner`'s own comment says it "is constructed once and reused, because building it raises the descriptor limit and reads the interface list, neither of which should happen per scan" (`ScanRunner.swift:53-58`). zhen-ios does the opposite, on purpose: `LiveScanRunner` builds a new one for **every** call (`zhen-ios/Zhen/Scanning/LiveScanRunner.swift:7-9`, `:48-50`). At launch, `load()` asks for `interface()` and `capabilities()`: two builds. Each scan builds one for `run()` and another for `interface()` afterwards (`zhen-ios/Zhen/Model/NetworkModel.swift:79-80`, `:144`). Each build reads the limit again (`getrlimit`, `sysctlbyname`) and calls `getifaddrs` twice (once in `make`, once in `ScanRunner.init` at `ScanRunner.swift:87`). `setrlimit` only runs while the limit still needs raising, so after the first build it's skipped (`DarwinPlatform.swift:92`). Cheap on iOS, where `make` opens no device, but the comment and the app disagree.
:::

::: iphone
📱 On iPhone & iPad

- ✅ The whole staircase runs. The first network door is the same unprivileged ICMP socket the Mac uses.
- ✅ No Wi-Fi? `make` finds no interface, `LiveScanRunner` turns the error into a `Degradation` and returns `.unavailable` (`zhen-ios/Zhen/Scanning/LiveScanRunner.swift:29-33`, `:52-58`). The app says "Connect to Wi-Fi and scan again."
- ✅ The screen stays awake for the length of a scan (`zhen-ios/Zhen/App/ScanHost.swift:16`).
- ❌ Lock the phone or switch apps and iOS suspends the scan. There's no background mode for this work (`zhen-ios/Zhen/Platform/IdleTimer.swift:6-8`).
:::

::: gotcha
⚠️ Gotchas the code remembers

- **Building the list from progress events.** The stream may drop events, so a list built from them can silently lose devices while still saying `complete` (`ScanRunner.swift:12-14`).
- **An unbounded stream.** `AsyncStream`'s default buffer is unbounded: "a memory leak with a progress bar on it". `StreamBuffering` has no `.unbounded` case at all (`ProbeStream.swift:3-11`).
- **A stream nobody finishes** hangs its reader forever. `performScan` calls `finish()` before awaiting the watcher (`zhen-ios/Zhen/Model/NetworkModel.swift:134-135`).
- **Getting isolation backwards** doesn't fail. "It compiles, it runs, and the scanner is quietly serialized" (`Package.swift:21-23`).
:::

::: remember
🧠 Remember

- A tap sets a **token**; `.task(id:)` is the only place a scan runs, and clearing the token stops it.
- **Two channels**: progress may drop, the result never does. The list comes from history.
- A **target boundary**, not an annotation, keeps sockets off the main actor.
:::
